# Frontier Insight Loop — 前沿输入认知沉淀闭环

## 目的

把"读一篇前沿文章 → 写总结 → 沉淀认知"变成可重复的标准流程。核心价值不是复述文章，而是以原文为唯一事实基准，纠正用户总结中的错误与漂移，再帮用户把观点提炼成可发布、可长期复用的个人认知资产。

## 触发场景

- 用户贴出前沿文章/博客链接，附上自己的总结或感悟，要求 review、核对、优化表述
- 用户说"帮我看看有没有需要优化的"、"沉淀成 skill"、"整理成推文/发布文案"
- 用户希望持续追踪某领域前沿输入并日积月累形成认知库

## 工作流程（按顺序执行）

### 步骤 1：抓取并通读原文（唯一事实基准）

- 先用 WebFetch 抓取链接。若返回为空，立即降级：`curl -sL -A "Mozilla/5.0 ..." <url> -o /tmp/article.html`，再用 Python 剥掉 `<script>`/`<style>` 标签提取正文存为 txt，然后用 Read 通读。
- 必须通读全文，不能只读开头。重点提取：关键数据、工具/项目专有名词、人物角色、原文直接引语、文章结论段的立场。
- 原文尚未抓到前，不得开始核对——没有事实基准的 review 是空谈。

### 步骤 2：逐条核对用户的总结

对用户的每一条总结给出分级判定，判定符号固定：

- `✅` 准确成立
- `⚠️` 方向对但表述需校准（偷换概念、数据缺失、过度概括）
- `❌` 事实错误（含写反的逻辑、张冠李戴、漏字导致意思反转）
- `💡` 原文有、但总结漏掉的高价值信息

每条判定必须附：原文依据（可引用关键句或数据）+ 具体修正建议。禁止只打标签不给证据。

高频错误类型（重点盯防）：
- 逻辑写反（如"引导 AI 出现幻觉"应为"防止/纠正幻觉性约束"）
- 错别字导致语义改变（注意中文输入法误写，如"中药"vs"重要"）
- 把原文的谦逊/限定条件删掉，变成绝对化断言（如原文说"不是 Git 的通用替代品"被总结成"放弃 Git"）
- 术语翻译不准确（如 telemetry ≠ 埋点，应作"遥测/监控数据"）
- 遗漏限定范围（如"适用于超大规模 monorepo"这类适用范围）

### 步骤 3：输出核对报告

按"总评 → 逐点核对（符号+证据+修正）→ 建议补充 → 优化后的总结"结构输出。优化后的总结要给出一个可直接复制使用的干净版本，保留用户原意但修正所有问题。

### 步骤 4：观点交锋（感悟层）

如果用户给出"感悟"，不要只说"说得对"。用有立场的方式拆解：哪些点最扎实、哪些点是入场券而非护城河、哪些标准正在改变、有没有原文隐含但用户没说的更高层论点。一切拆解须 grounded 在原文证据上，保持平实、不堆砌术语。

### 步骤 5：产出平实风格的发布文案

将核对后的总结 + 感悟打磨成可发布文案（默认推特/X 长帖风格，中文）。风格要求见 `references/style-and-review-guide.md`。默认版式：开头一句平淡的引子 → 编号短段落（每条加粗小标题）→ 结尾一段收敛感悟。不标题党、不用感叹号轰炸、不用"炸裂/颠覆/封神"类词汇。

### 步骤 6：闭环归档（保持长期领先的关键一步）

把本次沉淀追加到个人认知日志：

- 固定路径：用户 personal 目录下的 `frontier-cognition-log.md`（形如 `~/.workbuddy-ai/user-*-personal/frontier-cognition-log.md`，本机该目录唯一；文件不存在则创建）。首次使用时可先与用户确认一次日志落点。
- 条目格式（追加，不覆盖）：

```markdown
## YYYY-MM-DD | <文章标题>
- 来源：<URL>
- 核心事实：<2-3 条经核对的关键事实，含数据>
- 我的认知更新：<本次感悟的凝练版，1-3 条>
- 可复用句式/概念：<如 superfan、工程师作为编辑者 等>
```

- 追加后检查：若日志中同一主题（如 AI 工程化、Agent 基建）已出现过 ≥3 次，在回复中提示用户"该主题认知已形成聚类，可考虑整理成一篇系统性文章"——这是从输入到复利的关键钩子。

### 步骤 7：交付

最终回复包含：核对报告（可精简）、发布文案（完整）、归档确认（一句话说明日志路径与追加内容）。文案中如引用原文数据须确保与步骤 1 提取的一致。
