# 沉淀判定协议

解决一个问题：**收尾时怎么判断这次该不该写 skill**，而不是「怎么写 skill」。

## 与相邻 skill 的边界

| 需求 | 走谁 |
|---|---|
| 判断该不该沉淀、沉淀成什么 | **本 skill** |
| 从零写一个 skill 的写作技巧 | `skill-creator` |
| 在用 skill 的复盘迭代（打补丁 + 账本） | `skill-doctor` |
| 多工具分发、软链农场、推仓库 | `agent-skill-sync` |

## 一、判定：四问全过才沉淀

收尾时逐条过，不看「感觉有用」，只看证据：

| # | 问题 | 通过标准 | 反例 |
|---|---|---|---|
| Q1 | **会再发生吗** | 周期性任务，或同类场景已出现 ≥2 次 | 一次性调研、单次故障排查 |
| Q2 | **有固定常量吗** | ≥3 个「下次还得重查」的值：token / 路径 / 账号名 / profile / 命令 | 纯方法论、无具体对象 |
| Q3 | **踩过非显而易见的坑吗** | ≥1 个：报错后换路径才成功、文档没写但必须做的事 | 「注意规范」这类常识 |
| Q4 | **是一串动作吗** | ≥3 步可执行命令，有明确先后 | 纯知识说明、单一查询 |

判定结果：

- **4/4** → 建 skill（或改已有 skill）
- **2–3 个** → 先写 memory 观察一次；第二次复现再升级成 skill
- **≤1 个** → 不沉淀。写进当日 memory 即可

## 二、skill 还是 memory

| 内容性质 | 落点 | 理由 |
|---|---|---|
| 有动作序列、下次要照做 | **skill** | 可执行，能被 description 命中后直接跑 |
| 一条事实、一次事件、一个结论 | **memory** | 陈述性，不需要流程 |
| 既有时序又有事实 | **两个都写** | memory 记「这次发生了什么」，skill 记「下次怎么做」 |

## 三、产出规格：五段式

写 skill 时固定按这五段，缺一段就是半成品：

1. **固定对象表** —— 常量集中列表（token / 路径 / 主机 / 成员）。这是 Q2 的兑现，也是下次省时间的来源。
2. **流程** —— 每一步给可直接粘的命令，不给描述。参数写真实值。
3. **坑与边界** —— 每条格式：`症状 → 根因 → 修复命令`。只收「不看就会再踩」的。
4. **验收证据** —— 什么算做完：期望输出、退出码、要校验的字段。
5. **反例** —— 明确写「什么情况不要用本 skill」，防止误触发。

三条写作硬规则：

- **命令优先于描述**。写「用 A 加 B」不如写 `a --b`。
- **description 必须含真实触发语**。它是唯一被检索的字段，写「帮助处理相关事务」等于没有。
- **不写正确的废话**。「注意数据安全」「保持代码整洁」这类删掉。

## 四、迁移到其他 Agent（关键）

skill 文件本身可以复制，但**「收尾自检」这个习惯不会跟着复制**——除 WorkBuddy 内建提醒外，其余 Agent 只认各家的系统指令文件。所以迁移要做两件事：

### 4.1 技能本体

- 单机多工具：写到规范源 `~/.agents/skills/<name>/`，再 `~/.agents/scripts/sync-skill.sh <name>`（详见 `agent-skill-sync`）。
- 跨机器：把 `skills/` 目录推到私有仓库，目标机 clone 后软链进各自的 skills 目录。

### 4.2 规则注入（不做这步 = 只有当前工具有这个习惯）

把 `references/portable-rules.md` 里的规则块，粘进每个工具的系统指令文件：

| 工具 | 落点 | 形态 |
|---|---|---|
| WorkBuddy | `~/.workbuddy/SOUL.md`「行事准则」段 | 已被内建提醒覆盖，补一条口径即可 |
| Claude Code | `~/.claude/CLAUDE.md` | 追加一节 |
| Codex | `~/.codex/AGENTS.md` | 追加一节（可编号，如 §17） |
| Cursor | `~/.cursor/rules/sediment.mdc` | 新建 mdc，`globs` 留空表示全局 |
| Kiro | `~/.kiro/steering/*.md` | 追加一节 |
| 项目级 | 仓库 `AGENTS.md` / `CLAUDE.md` | 项目约定优先于全局 |

判据：**改完在任意一个工具里做一次「多步 + 踩坑」的任务，看它收尾时会不会主动提出沉淀**。不会，就是规则没生效或位置放错。

## 五、演进

- 每次真正用了本 skill 后，按 `skill-doctor` 复盘：判定标准是否误判、五段式哪段常缺，打补丁。
- 账本记 `~/.agents/skill-ledger/skill-sedimentation.md`：误判案例比成功案例更有价值。
