# 日报结构模板

核心骨架：**按项目分组 → 每条记录以「时段 · Agent · 干了什么」为行，附「产出/效果」列**。
行文克制（无空话、无 AI 味），表格优先。

## 0. 头部

```markdown
# Agent 工作日报 · <YYYY-MM-DD>（周X）

> 数据源：Wake wake.db（N 个 Coding Agent 会话聚合）
> 覆盖：<Agent 列表> · <N> 个活跃会话

## 一、今日总览

| Agent | 活跃会话 | 主要项目 | 一句话贡献 |
|---|---|---|---|
| codex | 3 | xxx | <10-20字> |
```

## 1. 总览表
- 每 Agent 一行；「一句话贡献」必须可被正文证据支撑。

## 2. 按项目详述（核心段）

每个项目/主题一个小节。小节内建议用「脉络时间线」——多 Agent 在同一个项目的协作按时间顺序排，
避免把同一战役拆散在多个 Agent 小节。

**记录条目格式（每事件行）**：

```markdown
### <项目/主题>

| 时段 | Agent | 干了什么 | 产出 / 效果 |
|---|---|---|---|
| 09:30–10:15 | codex | 拆 2 个子代理并行重构 QA 指派，测试先行 | 迁移 `20260904_0035_*` 落地；子代理产出待交叉审查 |
| 10:20–11:00 | cursor | 标注入口去冗余：移除文件批次 UI | 侧栏收敛为「我的任务」，可深链工作区 |
```

**填写要求**：
- `干了什么`：动词开头，描述目标/动作，不含结论性形容词。
- `产出 / 效果`：落点必须是**可验证产物**——文件路径、迁移名、HTTP 状态码、测试通过数、
  命令验收输出、外部交付物；无法验证时写"待验证/进行中"，**禁止编造**。
- 时段：取会话消息时间窗口；无时间戳消息（cursor 类）用会话 updated 时间近似并注明 ≈。
- 项目名缺失（如 cwd=home）写实际工作区名；实在无信息写 `(未知)`，不猜测。

## 3. 产出物清单

```markdown
## 三、产出物清单

| 产出 | 位置 | 状态 |
|---|---|---|
| <具体物> | <路径/分支> | 已完成 / 待审 / 进行中 |
```

- 状态必须与正文一致；「已完成」指有验证证据（测试/HTTP/文件存在），否则标待审。

## 4. 风险 / 备注（可选）

只写真实风险：待审查项、安全提示（如明文密码、外发数据）、未决问题、依赖阻塞。
无则省略该节，不要凑数。

## 5. 写作纪律（违反即返工）

1. 一切结论必须来自会话文本；数据查不到就写"无记录"，禁止脑补补全。
2. 一个会话可能跨多日（历史轮次混入）——只总结当日窗口内的动作。
3. 子代理会话（标题形如"你是 XXX 执行子代理"）归并到其父任务条目，不单独成节。
4. 涉及注册机/批量注册/破解类尝试：如实记录"无程序化出路"等最终结论，不做操作建议。
5. 涉密信息（API key、邀请码、密码）脱敏为 `***`，密码类写"已重置"即可。
6. 交付格式：Markdown 文件 `Agent日报_<date>.md`；写完用 present_files 呈现。
